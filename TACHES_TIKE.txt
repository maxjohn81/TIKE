TIKE - LISTE DES TÂCHES DE DÉVELOPPEMENT
Version : 1.0 - Plan de travail à valider
Document associé : CONCEPTION_TIKE.txt

INSTRUCTIONS À L’AGENT VS CODE
- Avant toute action, inspecter le projet existant et lire CONCEPTION_TIKE.txt.
- Ne pas supprimer/remplacer des fichiers existants sans expliquer pourquoi et obtenir confirmation si le risque est élevé.
- Avancer par petites étapes. À la fin de chaque phase, résumer les fichiers modifiés, les commandes exécutées et les tests.
- Ne pas commencer une phase dépendante si la précédente n’est pas validée.
- Ne pas implémenter les fonctionnalités non validées. Marquer clairement ce qui est simulé.
- Garder l’interface ultra simple, violette, en français.
- Ne pas remplir le code de données fictives permanentes : les données de démonstration doivent être dans un script SQL séparé.
- Toujours utiliser PreparedStatement, transactions SQL pour opérations multi-tables et mots de passe hashés.

ORDRE DE PRIORITÉ RECOMMANDÉ
Priorité P0 : audit, décisions de conception, connexion PostgreSQL, schéma, thème/navigation, authentification.
Priorité P1 : lieux/salles, événements, catégories, clients, vente atomique, paiement enregistré, billets uniques.
Priorité P2 : impression/QR Code, contrôle d’accès, tableau de bord, historique, export CSV.
Priorité P3 : réservations avec expiration, remboursements avancés, lecture caméra, PDF/graphes.

CRITÈRES DE FIN MINIMAUX
- L’application démarre et se connecte à PostgreSQL.
- Les rôles sont contrôlés.
- Les événements et catégories sont persistés.
- Une vente crée des billets uniques et un paiement cohérent.
- Le stock ne devient jamais négatif.
- Le contrôle refuse un billet impayé, annulé ou déjà utilisé.
- Les statistiques proviennent de la base de données.
- L’interface reste simple et violette.
- Les instructions de lancement sont documentées.
